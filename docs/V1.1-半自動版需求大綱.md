# V1.1(half automation)

# 半自動版需求大綱

## 一、專案定位

建立一套僅供核准客戶使用的私人訂購系統。

保留廠商親自與客戶核對訂單的服務方式，同時集中管理商品、庫存、訂單、運費及付款狀態。

## 二、帳號與權限

### 客戶帳號

- 預計100間公司，一間公司使用一組帳號
- 不開放公開註冊
- 管理員在後台建立帳號及臨時密碼
- 管理員自行透過LINE等方式交給客戶
- 第一次登入時強制修改臨時密碼
- 客戶可修改密碼及公司聯絡資料
- 忘記密碼時，由管理員重設臨時密碼
- 不包含自動邀請信及密碼重設信

### 管理員帳號

- 3組獨立管理員帳號
- 3位管理員權限相同
- 重要操作須留下紀錄

## 三、商品管理

管理員可以新增、修改、上下架及管理：

- 品牌
- 商品類別
- 商品
- SKU／口味／規格
- 價格
- 庫存

商品資料包含：

- 商品名稱
- 品牌
- 商品類別
- 商品描述
- 一張主要圖片
- 最多五張輔助圖片

SKU資料包含：

- 口味
- 規格
- 單位
- 價格
- 庫存數量

商品數量不預先限制，由管理員自行新增及維護。初始資料也由管理員輸入，51Code只負責建立系統。

## 四、客戶購物功能

客戶登入後可以：

- 依品牌及類別瀏覽商品
- 查看商品資料、價格及可購買庫存
- 將商品加入購物車
- 修改購買數量
- 刪除購物車商品
- 查看商品小計
- 查詢自己的歷史訂單

A版本不設定最低訂購金額，由管理員人工核對訂單。

## 五、配送方式

系統提供三種配送方式。

### 自取

- 客戶選擇自取地點
- 運費為NT$0
- 管理員可在後台新增、修改及刪除自取地點
- 每個地點可設定名稱、地址、聯絡方式及備註
- 訂單成立時保存當時選擇的地址，避免日後修改地址影響舊訂單

### 7-ELEVEN門市取貨

客戶手動填寫：

- 取件人姓名
- 手機號碼
- 門市名稱
- 門市店號

Phase 1不串接7-ELEVEN門市地圖或物流API，後續可列入Phase 2。

### 黑貓宅急便

客戶填寫：

- 收件人
- 聯絡電話
- 完整地址
- 配送備註

## 六、送出訂單前確認

客戶送出前須再次確認：

- 商品及規格
- 數量
- 商品單價
- 商品小計
- 收件人及聯絡資料
- 配送方式
- 自取地點、7-ELEVEN門市或宅配地址
- 配送備註

## 七、人工核對及運費流程

1. 客戶送出訂單。
2. 系統立即保留庫存。
3. 訂單進入「等待管理員核對」。
4. 系統不自動取消等待核對的訂單。
5. 管理員自行查看訂單並直接聯絡客戶。
6. 管理員可在核對階段修改商品、規格及數量。
7. 系統依修改內容同步調整保留庫存。
8. 若增加的數量超過可用庫存，系統不得儲存。
9. 管理員確認包裝與配送方式後，手動輸入運費。
10. 自取訂單的運費為NT$0。
11. 系統計算「商品小計＋運費＝最終付款金額」。
12. 管理員點擊「核對完成」後，訂單內容與金額鎖定。
13. 客戶可查看核對後的商品、運費及最終總額。

管理員只能在「等待核對」階段修改訂單。核對完成後若仍需修改，應取消訂單並重新建立，避免付款金額不一致。

## 八、付款流程

- 核對完成後，訂單進入「等待付款」
- 此時才開始48小時倒數
- 顯示固定銀行帳戶及固定付款QR Code
- 客戶自行輸入正確轉帳金額
- 客戶先填寫轉帳帳戶後五碼
- 再點擊「我已完成付款」
- 送出後停止48小時倒數
- 訂單進入「等待入帳確認」
- 管理員確認入帳後改為「準備出貨」
- 出貨完成後，管理員手動改為「已完成」

## 九、取消與逾期

- 客戶在提交付款確認前可以自行取消
- 客戶不需要填寫取消原因
- 管理員可以手動取消訂單
- 等待管理員核對期間不會自動取消
- 等待付款超過48小時，系統自動取消
- 取消或逾期後立即釋放保留庫存

## 十、庫存管理

- 每個SKU獨立管理庫存
- 客戶看到目前可購買數量
- 送出訂單後立即保留庫存
- 修改訂單時同步增減保留數量
- 取消或逾期時釋放庫存
- 管理員可手動調整庫存
- 庫存異動須留下紀錄
- Phase 1使用單一庫存池

## 十一、訂單管理

管理員可以：

- 查看及搜尋全部訂單
- 依訂單狀態篩選
- 修改等待核對中的訂單
- 輸入運費
- 完成訂單核對
- 確認款項入帳
- 取消訂單
- 更新準備出貨及已完成狀態

主要狀態：

1. 等待管理員核對
2. 等待付款
3. 等待入帳確認
4. 準備出貨
5. 已完成
6. 已取消
7. 已逾期

## 十二、通知

- 不發送新訂單Email或LINE通知
- 管理員自行登入後台查看
- 核對訂單由管理員直接聯絡客戶
- Phase 1不包含任何自動傳訊功能

## 十三、操作紀錄

系統記錄：

- 客戶帳號異動
- 商品與價格異動
- 庫存調整
- 管理員修改訂單的前後內容
- 運費異動
- 訂單狀態異動
- 執行操作的管理員及時間

操作紀錄保留3個月。

## 十四、基本設定

- 繁體中文介面
- 使用客戶現有網域
- 商品價格所有客戶相同
- 運費由管理員手動輸入
- 部署正式環境並提供基本操作交接
- 上線後提供60天Phase 1範圍內的Bug修復，不包含維護及新功能開發

## 十五、Phase 1不包含

- 公開註冊
- 自動邀請Email
- 新訂單通知
- 最低訂購金額
- 物流API及門市地圖串接
- 自動運費及裝箱計算
- 第三方金流或信用卡付款
- 自動產生不同付款QR Code
- 客戶個別價格及數量折扣
- Excel批次匯入
- 物流單自動建立及配送追蹤
- 多語言
- 多倉庫
- PDF發票或電子發票

# Semi-Automated System Requirements Overview

## 1. Project Positioning

Develop a private ordering system exclusively for approved clients.

Maintain the service model where vendors personally verify orders with clients, while centralizing the management of products, inventory, orders, shipping fees, and payment status.

## 2. Accounts and Permissions

### Client Accounts

- Approximately 100 companies, each using one account
- No public registration available
- Admin creates accounts and temporary passwords in the backend
- Admin delivers credentials to clients via LINE or other methods
- Mandatory password change upon first login
- Clients can update passwords and company contact information
- Password reset is handled by the admin with a new temporary password
- No automated invitation emails or password reset emails included

### Admin Accounts

- 3 independent admin accounts
- All admins have equal permissions
- Important operations must be logged

## 3. Product Management

Admins can create, edit, publish/unpublish, and manage:

- Brands
- Product categories
- Products
- SKU / flavors / specifications
- Pricing
- Inventory

Product data includes:

- Product name
- Brand
- Category
- Description
- One main image
- Up to five additional images

SKU data includes:

- Flavor
- Specification
- Unit
- Price
- Stock quantity

There is no preset limit on the number of products. Admins are responsible for data entry and maintenance. Initial data will also be entered by admins; 51Code is only responsible for system development.

## 4. Client Shopping Features

After logging in, clients can:

- Browse products by brand and category
- View product details, pricing, and available stock
- Add items to the cart
- Modify purchase quantities
- Remove items from the cart
- View subtotals
- Check their order history

Version A does not include a minimum order amount; admins will manually verify orders.

## 5. Delivery Methods

The system provides three delivery options:

### Self Pickup

- Clients select a pickup location
- Shipping fee is NT$0
- Admins can add, edit, and delete pickup locations
- Each location includes name, address, contact details, and notes
- The selected address is saved at the time of order to avoid future changes affecting past orders

### 7-ELEVEN Store Pickup

Clients manually input:

- Recipient name
- Mobile number
- Store name
- Store code

Phase 1 does not include integration with 7-ELEVEN store maps or logistics APIs; this may be included in Phase 2.

### Black Cat Delivery (Home Delivery)

Clients provide:

- Recipient name
- Contact phone number
- Full address
- Delivery notes

## 6. Pre-Submission Confirmation

Before submitting an order, clients must confirm:

- Products and specifications
- Quantities
- Unit prices
- Subtotals
- Recipient and contact information
- Delivery method
- Pickup location, 7-ELEVEN store, or delivery address
- Delivery notes

## 7. Manual Verification and Shipping Fee Process

1. Client submits the order
2. System immediately reserves inventory
3. Order enters “Pending Admin Verification”
4. Orders are not auto-cancelled during this stage
5. Admin reviews the order and contacts the client directly
6. Admin can modify products, specifications, and quantities
7. Inventory reservations are updated accordingly
8. System prevents saving if quantity exceeds available stock
9. Admin manually inputs shipping fee after confirming packaging and delivery
10. Self-pickup orders have NT$0 shipping fee
11. System calculates: subtotal + shipping fee = final amount
12. After clicking “Verification Complete,” order details and amount are locked
13. Client can view the verified order, shipping fee, and final total

Admins may only modify orders during the verification stage. If changes are needed afterward, the order should be cancelled and recreated to avoid discrepancies.

## 8. Payment Process

- After verification, order enters “Pending Payment”
- A 48-hour countdown starts at this stage
- Fixed bank account and QR code are displayed
- Client transfers the correct amount manually
- Client enters the last five digits of their account
- Then clicks “I have completed payment”
- Countdown stops after submission
- Order enters “Pending Payment Confirmation”
- Admin confirms receipt and updates status to “Preparing Shipment”
- After shipping, admin marks it as “Completed”

## 9. Cancellation and Expiry

- Clients can cancel before submitting payment confirmation
- No cancellation reason required
- Admins can cancel orders manually
- Orders are not auto-cancelled during verification stage
- Orders exceeding 48 hours in “Pending Payment” are automatically cancelled
- Inventory is released immediately upon cancellation or expiry

## 10. Inventory Management

- Inventory is managed per SKU
- Clients see available quantities
- Inventory is reserved upon order submission
- Adjusted dynamically when orders are modified
- Released upon cancellation or expiry
- Admins can manually adjust inventory
- All inventory changes must be logged
- Phase 1 uses a single inventory pool

## 11. Order Management

Admins can:

- View and search all orders
- Filter by order status
- Modify orders in verification stage
- Input shipping fees
- Complete verification
- Confirm payments
- Cancel orders
- Update shipment and completion status

Main statuses:

1. Pending Admin Verification
2. Pending Payment
3. Pending Payment Confirmation
4. Preparing Shipment
5. Completed
6. Cancelled
7. Expired

## 12. Notifications

- No email or LINE notifications for new orders
- Admins must log in to the backend to check
- Order verification is handled manually by admins contacting clients
- Phase 1 does not include any automated messaging

## 13. Activity Logs

The system records:

- Client account changes
- Product and pricing changes
- Inventory adjustments
- Before/after details of order modifications
- Shipping fee changes
- Order status changes
- Admin operator and timestamp

Logs are retained for 3 months.

## 14. Basic Settings

- Traditional Chinese interface
- Use client’s existing domain
- Same pricing for all clients
- Shipping fee entered manually by admin
- Deployment to production with basic training
- 60 days of Phase 1 bug fixes after launch (excluding maintenance and new feature development)

## 15. Not Included in Phase 1

- Public registration
- Automated invitation emails
- New order notifications
- Minimum order amount
- Logistics API and store map integration
- Automated shipping fee and packaging calculation
- Third-party payment or credit card support
- Dynamic payment QR codes
- Client-specific pricing or quantity discounts
- Excel batch import
- Automatic logistics order creation and tracking
- Multi-language support
- Multi-warehouse support
- PDF or electronic invoices
