## 總覽

| 需求核心 | 狀態 | 說明 |
|---|---|---|
| 僅核准客戶、不開放註冊 | 🔴 | 有公開 `/register`，任何人可自行註冊 |
| 品牌／類別／商品／SKU 四層 | ❌ | 只有單層扁平商品，`category` 為字串 |
| 三種配送方式＋運費核對 | ❌ | 只有單一宅配、運費寫死免費 |
| 7 種訂單狀態＋人工核對 | 🟡 | 現有 6 態語意不符，缺核對/入帳/逾期 |
| 庫存「保留」機制 | 🔴 | 下單直接扣庫存，取消不回補 |
| 48 小時付款倒數＋自動逾期 | ❌ | 無倒數、無排程；前端文案為「3 工作天」 |
| 操作紀錄（audit log） | ❌ | 無任何紀錄模型或機制 |

粗估：核心資料模型需重構，約 **60–70%** 需求尚未實作。

## 逐節對照

### §2 帳號與權限

| # | 需求 | 狀態 | 現況 / 位置 |
|---|---|---|---|
| 2.1 | 不開放公開註冊 | 🔴 | `POST /auth/register` 對外開放（`backend/app/api/endpoints/auth.py:16`） |
| 2.2 | 管理員後台建立帳號＋臨時密碼 | ❌ | 無 admin 建帳號端點 |
| 2.3 | 首次登入強制改臨時密碼 | ❌ | `User` 無 `must_change_password` / `is_temp_password` 欄位 |
| 2.4 | 客戶可改密碼、公司聯絡資料 | 🟡 | 有 `PUT /auth/profile` 但只存 `saved_address`，無公司資訊、無改密碼端點 |
| 2.5 | 忘記密碼由管理員重設臨時密碼 | ❌ | 無此端點 |
| 2.6 | 3 組同權限管理員 | 🟡 | `is_admin` 布林可支援，但無管理員管理介面 |
| 2.7 | 公司欄位（統編/聯絡人/電話等） | ❌ | `User` 無公司相關欄位 |

**`User` 現有欄位**：`id, email, username, hashed_password, is_admin, saved_address(JSON), created_at`

### §3 商品管理

| # | 需求 | 狀態 | 現況 / 位置 |
|---|---|---|---|
| 3.1 | 品牌（Brand）實體 | ❌ | 無 Brand model |
| 3.2 | 商品類別（Category）實體 | ❌ | `Product.category` 只是字串 |
| 3.3 | SKU / 口味 / 規格 / 單位 | ❌ | 無 SKU model；價格/庫存直接掛在 Product |
| 3.4 | 1 主圖 + 最多 5 輔圖 | ❌ | `Product.image` 僅單張 |
| 3.5 | 上下架（publish/unpublish） | ❌ | 無 `is_published` / `status` 欄位 |
| 3.6 | SKU 各自管理價格與庫存 | 🔴 | 價格/庫存在 Product，需搬到 SKU |

**`Product` 現有欄位**：`id, name, description, price, image, stock, category`

### §5 配送方式

### §7 人工核對 + 運費流程（整段缺）

| # | 需求 | 狀態 | 現況 / 位置 |
|---|---|---|---|
| 7.1 | 下單即進「等待核對」 | 🟡 | 進入 `PENDING`，但語意是「待付款」 |
| 7.2 | 管理員核對階段可改品項/數量 | ❌ | `update_order` 只允許改 status/payment_info |
| 7.3 | 改單同步調整保留庫存 | ❌ | 無 |
| 7.4 | 超過可用庫存不得儲存 | 🟡 | 建單有檢查，但改單無 |
| 7.5 | 管理員手動輸入運費 | ❌ | 訂單無 `shipping_fee` 欄位 |
| 7.6 | 小計 + 運費 = 最終金額 | 🔴 | `total_amount` 由前端傳入且未重算（`backend/app/api/endpoints/orders.py:53`） |
| 7.7 | 「核對完成」鎖定金額 | ❌ | 無鎖定狀態 |

### §11 訂單管理 / 狀態

現有狀態（`backend/app/models/order.py:8`）：
`PENDING / PAYMENT_SUBMITTED / CONFIRMED / SHIPPED / DELIVERED / CANCELLED`（6 種）

需求狀態（7 種）：
1. 等待管理員核對
2. 等待付款
3. 等待入帳確認
4. 準備出貨
5. 已完成
6. 已取消
7. 已逾期

| 問題 | 狀態 |
|---|---|
| 缺「等待入帳確認」 | ❌ |
| 缺「已逾期」 | ❌ |
| 缺「等待核對」語意（PENDING 目前=待付款） | 🟡 |
| admin 狀態下拉可任意跳轉，無流程約束 | 🟡（`src/pages/admin/AdminOrderDrawer.tsx:181`） |

## 已具備的基礎（可沿用）

- ✅ JWT 登入與權限相依（`get_current_user` / `get_current_admin_user`）
- ✅ 商品基本 CRUD、購物車、下單、我的訂單、admin 訂單清單
- ✅ 年齡驗證、多地址儲存（`saved_address`）
- ✅ 部署設定（Dockerfile / Zeabur / seed）

## 高風險項（優先處理）

1. 🔴 **公開註冊**未關閉 — 違反「僅核准客戶」核心定位
2. 🔴 **金額由前端傳入未重算** — 可被竄改
3. 🔴 **庫存直接扣除且取消不回補** — 庫存會漏、無法對帳
4. 🔴 前端付款文案 48h 不符

---

## 建議實作順序（詳見 refactor-plan.md）

1. 帳號管控：關閉註冊、臨時密碼、首次強制改密
2. 資料模型重構：Brand / Category / Product / SKU + 庫存保留
3. 訂單狀態機重構（7 態）+ 後端金額重算
4. 三種配送方式 + 自取地點管理 + 地址快照
5. 人工核對 + 運費輸入 + 核對鎖定
6. 48h 付款倒數 + 自動逾期排程 + 庫存釋放
7. 操作紀錄（audit log）
